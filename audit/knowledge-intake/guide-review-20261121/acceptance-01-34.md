# 承認機能の実装引き継ぎと受入条件34件

4種類の人による独立承認（解説、特徴検索、食毒、公開）を維持する。#158の01–24、#159の25–34の検体と期待結果は下表に原文のまま統合した。機能実装前の受入条件であり、今回は現行v1と既存機能のみテストした。

| 実装時に検証する面 | 主な受入ID | 仕様上の要点 |
| --- | --- | --- |
| 管理室の審査画面と承認履歴 | 01–07、15–17、23、25、29、33 | 承認は欄ごと。根拠と差分・基準mainを画面に表示。再承認を履歴に残す |
| 候補の検証・重複防止 | 07–11、14–18、24、26–29、31–32、34 | 現行v1は厳密なmain照合。新経路は範囲を限定した差分検証と保護比較を最新mainで実行 |
| 写真への接続と公開生成 | 02–04、12–13、19–22、29–30 | 掲載先は承認済みの対応のみ。接続が疑わしい写真を保留し、既存公開を保全 |
| 食毒の表示 | 02、05–06、29、33 | 未決の構造化値は `unknown`。解説本文・出典注記・キャプション・検索用の文を経由する安全性の断定も公開前に審査する |

mainが更新されると未公開の旧承認は失効する。根拠・分類・定義・掲載先と依存する規則が変わらなかったことを比較で確かめられた解説と特徴検索は、管理者が対象を確認して再承認できる。食毒と公開は個別に再承認する。比較できない場合は該当範囲を個別審査へ戻す。先行設計の詳細は [#159の再審査設計](https://github.com/charchan123/hatena-photo-gallery/blob/0104ef5860ed47ed3ce8d27af7bd1dddb477871a/audit/knowledge-intake/guide-continuation-20261121/main-update-review-design.md) に従う。

## 受入条件

| ID | 検体・操作 | 期待結果 |
| --- | --- | --- |
| 01 | 引用・範囲・出典が揃った解説を承認 | 解説だけが承認済み。v1台帳、公開ビルド、特徴索引に差分なし |
| 02 | 解説承認済み、食毒未決、明示した公開承認あり | 該当詳細に解説。食毒は `unknown`、当該特徴検索には出ない |
| 03 | 特徴承認済み、公開未決 | 審査履歴に記録。検索から未公開ページへ遷移しない |
| 04 | 公開後に特定の特徴IDだけを承認 | その特徴から正しい公開詳細へ遷移。他の索引を変えない |
| 05 | 食毒未決、本文中で食べられると記載 | 解説の承認を遮断。本文・安全欄両方を審査対象にする |
| 06 | 旧学名の中毒例に複数の現行種が対応 | 食毒は `unknown`。人の同定範囲確認へ |
| 07 | ページ位置、根拠URL、原文ハッシュの欠損・不一致 | その主張の承認を遮断し、原稿と既存データを保持 |
| 08 | 改変した差分／壊れたマニフェスト／候補のパストラバーサル | 採用・公開前に検証停止。許可外ファイルに書き込まない |
| 09 | 同じID、和名、別名がmainやv1に存在 | 既存行を保持。候補を衝突表示し解決まで停止 |
| 10 | 空白・全半角だけが異なる和名、学名だけが一致する別項目 | 名前の衝突を報告。学名だけでレコードを統合しない |
| 11 | 既存IDの根拠付き改訂 | 新しいIDを追加せず、対象旧版とレビュー差分を記録 |
| 12 | 疑問符付き・複合ラベル・科のみ・別名重複 | 接続候補は保留。既存詳細と画像遷移を維持 |
| 13 | 承認後に写真ラベル変更、掲載キー消滅、観察退役 | 接続を再審査。旧候補が異なる観察に接続されない |
| 14 | 同じmainから同一IDを含む2つのDraftを並行作成 | 後着の採用を最新mainで停止。CIで競合を報告 |
| 15 | 一覧表示後にmainが進む | 旧画面からの承認は失敗。新差分と再審査リンク表示 |
| 16 | 承認後に候補本文・出典・接続・ベースのいずれかが変更 | 未公開承認が失効し、影響範囲を表示。承認は新ハッシュに自動転送されない |
| 17 | 同じ承認を再送、別タブで旧版を承認、途中で処理を中断 | 同一イベントを重複記録せず、古いイベントを拒否。再実行で整合 |
| 18 | v1の正規バッチ、無承認特徴と解説だけのv1候補 | 正規v1を処理。無承認の特徴と対応する特徴を欠くv1候補は従来どおり拒否 |
| 19 | 日次同期の既存記事・新規記事・保護写真の削除申請を再生 | 記事抽出・同期処理・保護と退役の基準出力が一致 |
| 20 | 固定スナップショットの全生成と回帰比較 | 写真933枚、研究室66ケース、Best Shot17件のIDと順序を保全。同一入力間でLightGalleryの起動、戻る操作、スクロール復帰を比較 |
| 21 | レジストリの壊れた新データ | 新しい公開を停止。既に公開された承認済み版を使い、失敗を運用側に示す |
| 22 | 公開処理が失敗／公開済み版を承認付きで取り下げ | 成功確認まで公開済み数を増やさない。取り下げで元の写真・記事を残す |
| 23 | 管理室デスクトップ・スマホで未決→保留→再審査 | 4欄が独立して操作でき、判定履歴と次の操作がキーボードとタッチで確認できる |
| 24 | CIから承認データの書換・非Draft PR作成・差分範囲外の変更を試す | 書き込みを許可せず、候補PRを遮断。mainへの反映には個別承認を要する |
| 25 | mainの別文書だけ更新 | 旧承認失効。4欄の内容一致を表示し、担当者の操作で新しいSHAに記録。自動承認なし |
| 26 | 別原稿で同じ和名・別名・学名参照を追加 | 名寄せの比較結果が変化。衝突を表示し、関係する承認欄を個別審査 |
| 27 | 共通出典の本文だけ変更、URLは同じ | 取得原文のハッシュ差を検知し、依存する欄だけ簡易確認から除外。出典未取得でも再審査 |
| 28 | 特徴定義だけ変更 | 該当する特徴とその公開への影響を確認。関係ない解説は変更なし確認に進める |
| 29 | 食毒区分の規則変更、承認の適用範囲に差 | 食毒と公開を個別審査。審査前の安全区分は `unknown` |
| 30 | 接続先の観察が退役、掲載ラベルが疑問符付きに変化 | 公開接続を遮断し差分を表示。既存写真の状態は従来の扱い |
| 31 | 同時に別PRが同じIDを採用、比較画面と保存の間にmainが動く | 古い画面からの再承認を拒否。再比較で新しい衝突を表示 |
| 32 | 生成規則の不明な変更、比較に未収集の依存がある | 簡易確認に進めず、対象範囲を再審査 |
| 33 | 複数欄の再承認画面をスマートフォンで操作 | 承認対象が明示され、食毒・公開は個別操作。前回版と今回版を履歴から追跡可能 |
| 34 | v1バッチに新経路の簡易確認履歴を混ぜる | 従来の要求を満たさないv1候補を拒否。最新mainの確認を省略できない |
