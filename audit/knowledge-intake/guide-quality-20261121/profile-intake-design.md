# 図鑑解説を先に審査する設計案

検討日 2026-11-21。基準 main は `f19541524a989f2ab1979c78a9bff5e5e0274092`。この文書は設計レビュー用で、管理室や公開環境の実装変更を含まない。

## 現行の制約

管理室の `admin/knowledge.py` は候補を特徴検索向けの `assignment_additions` として審査する。取り込み検証で、新規マスターには対応する特徴候補が必須。オーバーレイ再構成でも、解説に形質の記述を持つ新規種には承認済みの特徴が必要となる。特徴の承認記録から、同じ種のマスター、出典、原文スナップショットが一緒に採用される。

`mushroom_knowledge.py` のマスター読込は学名・安全情報・形質・発生時期・生育環境の参照先を検証する。ここでの検証対象は出典レコードとの参照整合性。解説を単独で取り込む場合は、文ごとの出典と分類が適用される範囲を審査する追加契約が要る。

`admin/git_workflow.py` の採用PR作成は、チェックアウトとバッチが最新の `origin/main` に一致することを確認し、既存のレジストリと3つのデータファイルを許可リストで保護している。現行の `gh pr create` 呼び出しに `--draft` はない。新経路では明示的なDraft作成を要件に含める。

## 提案

### 1. 解説の採用を独立させる

新しい形式の解説候補を管理室で扱う。承認単位は1種1原稿。候補は安定したマスターID、掲載名、資料掲載学名と分類の適用範囲、出典付きの説明文を持つ。主要な主張は、どの項目に対応する文か、資料のページ・節、短い根拠箇所、取得原文と抜粋のハッシュを持つ。原文取得が再現できない主張や未解決の分類は保留できる。食毒を記載する場合は、対象学名・標本または事例の範囲・出典を個別に確認し、保留した値は `unknown` を維持する。説明文を承認しても食毒の判断は引き継がない。

既存マスターと既存の特徴用レジストリを保持したまま、追加専用の解説レジストリを新設する。独立したバリデータが基準マスターを読み、両方のデータでID・正式和名・登録済み別名・出典IDの衝突を拒否する。同じ学名や別名の可能性があるレコードは人の照合対象とする。正当な再版は別レコードの追加で扱わず、別途承認した改訂経路で旧版と新しい原稿のハッシュを紐付ける。

第1段階は採用済みレコードを図鑑詳細向けにだけ投影する。掲載名からの表示接続は、採用操作とは別の明示的な確認を要件とする。#149相当の完全一致を使い、既存辞書に同名がある場合も解説IDの表示参照だけを扱う。記事本文からの名前抽出、分類辞書の判定、写真ID、研究室、同期前後の観察データは現行の経路を使う。特徴検索用のマスターや既存スナップショットとのバイト一致条件を維持する。

### 2. 特徴検索は根拠がそろった形質単位で審査する

特徴検索の承認単位はマスターID × 特徴ID。根拠の短い原文と位置、出典・原文のハッシュ、特徴IDの適用条件、対象の解説改訂IDを紐付ける。解説だけが承認された種は、特徴検索の対象外理由として「根拠審査未完了」を表示する。承認済み特徴があっても解説が公開未接続なら、公開ページへの遷移先ができるまで検索結果の公開を保留する。

次段階で新形式の特徴用オーバーレイを作る場合は、既存v1オーバーレイを従来の検証器で再構成した後に適用する。新形式の検証器が承認済み解説IDの集合と特徴IDの許可リストを照合し、正確に承認された分だけを足す。旧形式のスキーマと、既存の特徴追加に根拠・承認を要求するルールは従来どおり。新形式の表示・検索・審査待ち件数を別の集計にし、旧v1に空の特徴行を作らない。

## 管理室・GitHub・同期への適用順

1. **読み取り専用の原稿一覧**。旧形式も読み込める状態で、掲載名、資料、毒性判定、特徴検索、最終表示が見分けられる一覧と差分プレビューを作る。承認状態は候補の内容ハッシュと基準mainに結びつける。
2. **承認済み解説だけのDraft生成**。既存の隔離worktree・許可リスト・確定差分を再利用する。新経路の許可先は解説用レジストリとそのパッケージに限定し、CIで基準と追加分を再構成して比較する。PR作成はDraftを明示する。データ採用と掲載名への接続を別操作にする。
3. **特徴検索だけの追加**。採用済み解説を参照できる特徴候補の審査を実装し、表示上の件数と旧特徴検索の同一性を検証する。
4. **公開承認後の接続**。隔離環境で日次同期相当の全生成とブラウザ回帰テストを通し、公開の個別承認を得る。保護テストの完全一致が必要な基準データと、承認済みの追加パッケージの照合対象を明示する。

採用の直前に最新mainを取得し、checkout・候補・確認済み差分が同じ基準かを照合する。PR作成前とCIでもbaseの移動と重複を再検査する。mainが進んだ場合は候補を再検証して、対象行と先行採用分の差分の確認に戻す。既存の承認を新ハッシュへコピーしない。並行して開いている候補同士は事前に警告し、headとbaseの再確認で二重追加を防ぐ。#150〜#155を投入する順序で旧59種パックを混ぜない。採用済みIDと別名を見て、重複がある候補の判断は中断する。

## 受入テスト

| 検体 | 期待結果 |
| --- | --- |
| 承認済み解説＋特徴未決 | 詳細ページだけに出る。新しい特徴検索結果は発生しない |
| 解説未決・出典欠損・原文ハッシュ不一致 | 公開データの生成前に停止 |
| 同一マスターID・和名・別名を再投入 | 後続追加を拒否。既存レコードを保全 |
| 古いmain・承認後に変わった原稿・並行PRの重複 | 正式な候補を書き出す前に停止し、再照合へ戻る |
| 毒性の分類範囲が未確定 | 食毒欄は `unknown`、食用や毒性の断定に変換されない |
| 写真 ID・記事抽出・研究室・Best Shot・LightGallery・日次同期 | 対象外の差分がないことを、公表データとCIで照合 |
| 旧v1の正規候補・無承認の特徴 | 正規候補は通り、承認を欠く特徴は従来の契約で拒否 |

解説先行で最初に検証する候補は、頭部の形や宿主が主な特徴のハチタケ・カメムシタケなど。特徴分類に確実に対応する根拠がある原稿は、既存の入口を引き続き利用できる。
