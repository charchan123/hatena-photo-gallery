# 管理室の図鑑確認・承認の設計案

## 現行機能と再利用先

| 現行機能 | 確認した挙動 | 次段階で再利用する部分 |
| --- | --- | --- |
| [管理室の情報拡充](../../admin/knowledge.py) | バッチ・原稿・特徴割当と出典を検証し、ハッシュに紐付けて候補ごとの採用・保留・未決とノートをローカルに保存。採用パッケージは最新main・候補の決定・既存v1検証を確認 | 原稿表示、出典、バッチ照合と差分検証は再利用。原稿だけを審査する場合は特徴承認と別のレコードにする |
| [日次同期の確認](../../admin/sync.py)・[写真の手動採用](../../admin/sync_adoption.py)・[例外](../../admin/sync_exception.py) | 観測IDに加え、記事IDのハッシュ、画像URLのハッシュと記事内出現順、画像内容、元データの状態を照合。プレビュー・明示確認・Draft PRの直前に鮮度を検証。写真の手動採用は未掲載の一意な対象用 | 写真の識別と再照合の考え方を使う。掲載済みの図鑑解説対象は同期の採用・名称変更の対象へ送らない |
| [自動保存・復元](../../admin/draft_store.py) | 許可済みの3ファイルの下書きを原子的に保存。元データの変更時は保管済み下書きを維持して停止 | 新しい下書きは専用名前空間に保存し、原子的な保存と復元時の照合を同様に適用。既存3ファイルの許可リストを変更しない |
| [Draft PR作成](../../admin/git_workflow.py)・[管理室API](../../admin/server.py) | 操作別に変更ファイルを制限し、独立した作業ツリーで差分と最新版の整合性を検証。Draft作成前に保存済み状態を確認 | 新規経路は専用マニフェストと監査差分を対象に、同じ作業ツリーの分離・許可パスと明示的な生成操作を採用。実装が決まるまでは既存経路から分離 |
| [詳細の生成](../../detail_ui.py)・[図鑑専用追加データ](../../data/guide-expansion.json) | 解説が紐付いたIDで読む設計。追加20種を特徴検索用マスターから分離し、既存の食毒警告・出典を表示 | 詳細に接続する候補は明示的に指定。掲載名・別名の類似でリンクを広げない。複合カットを除外しても全写真に解説が適用される現行設計では、接続処理自体を保留 |

## 審査対象とデータの対応

| 審査 | 承認が及ぶ範囲 | 再審査の条件 |
| --- | --- | --- |
| 写真と名称 | 掲載キーと照合済み画像の観測IDの集合。各写真に記事安定ID、出現位置、画像URL・内容のSHA-256、現在の名前と分類状態、日付、根拠・理由を保存 | 観測ID・画像内容・分類・記録の変更。全写真を対象にした記録は写真の追加・削除でも再審査。1枚ずつの確認記録はその写真の変更分だけを再審査 |
| 図鑑解説 | 正規マスターID、和名・学名の適用範囲、本文改訂、出典ID・該当箇所と必要なハッシュ | 文章・根拠・分類範囲の変更、同一学名・和名・別名の競合、出典の欠落や差し替え |
| 特徴検索 | 対象形質と明示的な出典根拠、現行の絞り込み定義 | 形質と根拠の変更、依存する定義の変更。現行v1の採用は従来どおり |
| 食毒 | 対象学名・地域・資料の適用範囲、状態、警告文改訂 | 根拠、適用範囲、区分、警告の変更。症例を近縁種へ広げない。食毒未決は承認された unknown の表示ポリシーを適用し、解説本文へ迂回させない |
| 公開 | 選んだ審査記録の改訂、必要な公開物の差分、対象観測ID集合、main SHA・生成ツリー | 候補、承認範囲、差分、生成結果、本番基準が変化したとき。依存する承認が揃うまではDraftに留める |

確認記録のイベントは reviewer・確認日時・scope・digest・basis revision・適用対象・理由を保存し、修正は履歴に追記します。表示した観測IDに加え、同じURLで画像が置き換わっていないことを確かめます。サーバーが再計算した画像ハッシュが取得できないときは未確認を維持します。プレビューのハッシュはポータルと記事照合に基づく作業用の値です。

mainが動いたときは全ファイルを一律に審査し直す前に、承認別の依存ファイル・レコードと承認対象の差分を再計算します。差分のない項目の審査記録を保持し、関連する写真・原稿・根拠に変化がある項目だけを再審査します。公開候補は改めて新しいmainから生成し、既存の保護試験を通し、今回の差分に対する人間の最終判断を記録します。取得失敗・複数マスター衝突・変更範囲を計算できない場合は公開パッケージ作成を止めます。別ブラウザや同時操作からの上書きは保存版の比較で止めます。

既存 [#158](https://github.com/charchan123/hatena-photo-gallery/pull/158/files)・[#159](https://github.com/charchan123/hatena-photo-gallery/pull/159/files)・[#160](https://github.com/charchan123/hatena-photo-gallery/pull/160/files) の独立承認と受入条件01〜34を引き継ぎます。図鑑専用の新規解説は既存マスター141種、追加マスター20種、既存の和名・別名・出典IDとの完全一致と衝突を検査し、候補を上書きせず人間に提示します。

## 画面での確認順

1. 一覧は優先順・写真数・名称・確認状態で絞り込みます。確認が必要な画像を先頭に出し、元記事の見出し・写真キャプション・公開写真を同時に見ます。
2. Bは写真セットを一画面で見せ、別種や比較用の写真があれば写真単位の確認に切り替えます。全写真を確認できる場合だけ、選択したIDと枚数を見せて名称確認を記録します。Aは過去の確認範囲と現在の照合結果を見せます。Cは問題の画像から確認します。D・Eは未解決事項を示して保留できます。
3. 写真側の判断と原稿側の判断は別画面・別ボタンにします。既存原稿の資料掲載学名・根拠・対象地域が一緒に確認できるようにします。個別記録と全写真の確認を区別し、保留を次回の一覧に残します。
4. 中断後は保存日時・再確認が必要なもの・前回の対象を表示します。採用機能の設計審査後は、対象を絞った差分を表示し、明示操作でDraft PRへ進めるようにします。

## 追加の受入検証

| ケース | 期待結果 |
| --- | --- |
| #163の3枚のURLが一致し、同じ掲載ページに新規写真1枚 | 旧範囲は3枚まで。新規写真へ一括適用しない。全体の公開を保留 |
| 画像URLは同一、画像バイトが置換 | 承認対象から外して再確認 |
| 記事中の比較写真や複合カット | 個別の説明・確認理由を記録。全体に接続するDraftの作成は中止 |
| 同じ和名・旧名が別の分類群に対応 | 範囲を人間が審査するまで保留。似た名前への自動接続なし |
| 写真1枚だけ未確認、原稿は審査済み | 原稿の審査記録は保持。現在の全写真向け解説には接続しない |
| 未承認の食毒文を原稿または出典注記へ追加 | 読者向け差分の検証で拒否。個別審査の候補データは保持 |
| mainに無関係な監査資料を追加 | 依存する対象と記録を再計算。既存の対象別確認は保持し、公開差分は再生成 |
| 本文の根拠が変更、または表示用出典に衝突 | 当該原稿と下流の公開の審査を戻す。無関係な写真の確認を保持 |
| ローカル下書きの破損・別タブ書込み・古いデータ | 上書きせず通知。書き出し前の記録を保持し、旧記録を現行の進捗に加算しない |
| Draft生成・マージ前の許可パス照合 | 管理室・同期・既存写真・記事・分類・日付・既存リンク・既存105種と出典・Best Shot・研究室・コメントに差分があれば停止 |

[独立プレビュー](preview/index.html)では一覧、写真、根拠、ローカル確認の流れを試せます。実際の承認、PR生成、公開はこの画面から呼び出しません。
