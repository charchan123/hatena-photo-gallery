# 管理室へ原稿候補を引き継ぐ方法

## 現時点のデータ

最新main上に置く監査専用データです。管理室 #186 のカタログ、プログラム、SQLite、承認の書き出しファイルへの運用上の接続はありません。優先65の判定は #185 のBかつ旧v1検証済み64項目と旧センニンタケ候補1項目を、#186 の `priority_candidate` と集合で照合しています。残りの再審査候補24項目と、既存の追補を独立化した2項目も保持します。

| 原稿データ | #186カタログとの照合と将来の対応 |
| --- | --- |
| `gallery_name` と `catalog_key_sha256` | `items[].name` と `admin/guide_review.py` の名称キーを完全一致で照合。分類・alias検索の入口には使わない |
| `catalog_item_sha256` | 固定HEAD #186 のカタログ項目の整列JSON（UTF-8、空白なし）を SHA-256。比較起点。原稿を取り込む時点では最新のカタログと掲載グループの観測範囲を再計算 |
| `candidate_id` と `proposed_master_id` | 候補の管理IDと正規マスター候補IDを分離。既存v1候補は従来のIDを引き継ぐ。調査段階の新IDは `proposal-…` を使い、旧学名と同じ種を指すと承認されるまで正式マスターIDに昇格させない。分類群が定まらない記録は null |
| `taxon_scope`、`scientific_source_name`、`scope_checks` | 表示には資料掲載学名だけを使う。旧学名・改訂候補・個別標本への適用は注記とする。同一候補IDの別分類群へ変更する場合は新しい審査が必要 |
| `fields` | `scientific/family/genus/ecology/features/habitat/season/food` を `draft.fields` の「資料掲載学名／科／属／生態／特徴／生育環境／発生時期／食毒」に対応。注意事項は原稿プレビューの注記。未確認欄は空または現行の未確認表示 |
| `source_ids`、各欄の `source_location` | 出典一覧のID・URL・対象ページ等を解決し、`draft.sources` 形式の出典ID・URL・資料名に変換。旧原稿の根拠が書誌だけの場合は位置の再確認を要求 |
| `revision_sha256` | ハッシュ欄を除いた原稿全体の整列JSONを SHA-256。採用候補の本文・出典範囲・明示した未確認事項の改訂を識別 |
| `approval_requirements` | 写真と名称、本文、食毒、検索特徴、公開の5つを別に審査する。監査ファイルは承認処理の入力ではない |

## 管理室の再開後に行う照合

1. 最新main・gh-pages・#185と#186のHEADを確認し、`verify.py` の読取照合を実施します。#186の実機試験は、既存の引き継ぎ記録どおりZIPのSHA-256照合から再開します。
2. `field-matrix-91.csv` の掲載名・原稿ID・マスター候補IDを確認し、現行マスター／追加マスター／既存別名・同名との衝突を調べます。変更があれば対応する候補だけを再審査します。
3. 設計・接続の個別承認後に、上表の変換を隔離した候補プレビューに適用します。#186のプレビュー用カタログは旧資料の改訂番号や確認記録に紐付くため、承認履歴を含むDBへ直接コピーしません。表示候補の本文や根拠が変わる場合、旧原稿の承認は改訂後へ移行しません。
4. この候補には `features`（特徴の説明）があります。特徴検索の分類への割当は別審査で、`features_search` の承認を必要とします。食毒はすべて未確認で、原稿本文からの転用も避けます。#186で生じた試験記録や試験の確認者は正式審査に適用しません。
5. センニンタケは #163 が記録した3枚だけを現在の観測ID・画像内容・記事・分類状態と再照合します。旧記録は解説、食毒、特徴検索、公開の承認を含みません。
6. 原稿と写真の適用範囲を別々に確認した結果を、独立した検証・承認手順へ渡します。現行v1の採用条件はそのまま使用します。
