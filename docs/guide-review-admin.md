# 管理室「図鑑情報の確認」実機試験

写真を撮影した人が、公開写真と掲載名を照合し、図鑑原稿の審査へ進むための画面です。操作による変更は管理室の確認記録に保存されます。図鑑への接続や公開の操作はこの段階では使えません。

## 画面で確認する順序

1. 左メニューの「図鑑情報の確認」を開きます。最初は既存原稿の検証履歴がある64項目とセンニンタケを表示します。「すべて」では125項目と関連1件を表示します。検索欄にはひらがなでも入力できます。
2. 確認者名を入れます。写真はタップで拡大できます。「記事の該当箇所と写真ID」から元記事の記述や撮影日を確認できます。
3. 表示できた写真を確認し、対象全体を判断できるときは「全○枚の名称を確認して次へ」を押します。判断が分かれる場合は「写真ごとに確認」を選びます。C〜Eの項目は写真ごとに確認します。関連資料や画像が揃わない場合は保留できます。
4. 「図鑑原稿・出典・個別審査」から原稿や出典を確認します。原稿・食毒は内容と根拠を確認し、審査結果を明示して保存します。特徴検索は候補を「情報拡充」から参照し、この段階では保留・訂正を記録できます。公開の欄は後工程です。
5. 保存結果と改訂番号を確認します。「確認履歴」に確認時点の写真範囲、確認者、メモが残ります。「名称確認を訂正・再確認」は過去の履歴を残したまま、現在の判定を見直す操作です。

センニンタケの「旧承認の指定3枚を再確認して保存」はPR #163で指定された3枚だけを対象にします。現在の全公開写真を確認する操作は別にあります。

### 保存と再開

操作したときにSQLiteへ保存します。通常の管理室では `admin/local-state/guide-review.sqlite3`、試験版ではユーザープロファイル内の `KinokoGuideReviewTrial/admin/local-state/guide-review.sqlite3` を使います。確認者名とメモはバックアップに含まれるため、ご自身のPCで保管してください。

他のタブで保存されていた場合は「公開データと保存記録を再取得」を押し、変更を見直してから操作をやり直します。再起動時に履歴と原稿審査を読み込みます。確認済み写真の画像は、項目を開くとその時点の画像と再照合されます。それまでは画像の再照合待ちとして集計します。画像の追加・削除・差し替え、記事の改訂は、関係する項目を再確認にします。

「JSONを書き出す」で履歴を退避し、「選んだJSONを取り込む」で同一系統の不足分を復元できます。取り込んだ確認結果は出所を表示し、再確認を求めます。別系統の履歴や破損したファイルは拒否されます。SQLite破損時に試験の復旧が必要な場合は、試験を終了し、元ファイルを別名で保管してから再起動し、書き出したJSONを取り込んでください。

### Windows PCで起動する

Draft PRの「Read-only guide review admin」から、テスト成果物のWindows用ZIPとSHA-256を取得します。ZIPを展開し、PowerShellを展開先で開いてください。

1. Pythonを確認します。`py.exe -3 --version` を実行します。
2. 初回は展開先に試験専用の仮想環境を作ります。`py.exe -3 -m venv .venv` を実行します。
3. `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` を実行します。
4. `.\.venv\Scripts\python.exe tools\guide_review_trial.py` を実行します。ブラウザーで <http://127.0.0.1:8765/> を開きます。
5. 「図鑑情報の確認」を開き、拡大、個別確認、全体確認、保留、再読込、履歴の順に試します。公開データと写真を読むため、インターネット接続を使用します。終了はPowerShellで `Ctrl+C` です。

依存関係を導入済みの通常のPythonで試験する場合は、同梱の `Start-Guide-Review.cmd` からも起動できます。通常の管理室は従来の方法で起動できます。

### Androidで同じ画面を試す

PCの試験版を起動したまま、AndroidをUSBで接続します。Android SDK Platform-Toolsがあり、ご自身のPCを端末で信頼済みの場合に実施できます。

1. Windowsで `adb reverse tcp:8765 tcp:8765` を実行します。
2. AndroidのChromeで <http://127.0.0.1:8765/> を開きます。
3. 「図鑑情報の確認」を開き、拡大、320px相当の狭い表示、確認ボタン、履歴を試します。記録は同じPCの試験用DBに保存されます。
4. 試験後はWindowsで `adb reverse --remove tcp:8765` を実行し、PowerShellで試験版を終了します。

サーバーの待受先はPCのループバックのみです。試験版では図鑑確認用のAPIだけを使用でき、管理室の既存の書き込み機能や外部管理サービスへの接続は実行されません。

## 実装と検証

- PR #185の監査CSV、原稿インデックス、出典、原稿追補と安定記事IDを、公開時の観測IDに結び付けて取り込みました。`tools/build_guide_review_catalog.py` に取得時点と件数検証があります。調査画面の状態・ブラウザ保存コードは引き継いでいません。
- 現在公開中の `portal-data.json` と照合し、同じ掲載名の公開写真を列挙します。異動や既存原稿にない項目も、次回の資料改訂で追加できます。既存履歴の参照先を保つため、履歴がある項目は資料から消さず、公開対象の写真が0枚の状態を許容します。
- 拡大は管理室内のダイアログで行います。公開側のLightGalleryと共通CSSは従来どおりです。
- 自動テストは写真取得エラー、再読込、明示操作、鮮度、破損記録、別タブの競合、履歴の再確認、審査の独立性を確認します。ブラウザテストでは1440・390・320pxで126項目の画面を開いて、写真範囲と横方向のはみ出しを調べます。
- 最初に検証した公開 `4d12205a98e640448b17883e4e89f1ab64a9fd50` は935枚、313掲載項目、図鑑解説105種、マスター141種＋追加20種です。
